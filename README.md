# Alundra Randomizer (Java)

An item randomizer for **Alundra** (PlayStation, 1997), working on a **US v1.1** disc image. It shuffles the items
found in chests, shops and NPC rewards, guarantees every generated seed can be completed, writes hints in
characters' dialogues and patches the game to make it enjoyable in a non-linear format.

This project is a Java port of [Dinopony/alundra-randomizer](https://github.com/Dinopony/alundra-randomizer) (C++,
v1.2.0). The logic data, patches and algorithms come from that project; the Java version reproduces them exactly
(see [Verification](#verification)) and adds its own disc image handling so that no external tool is needed.

## Game flow

- The game starts inside Jess's house.
- Most cutscenes and scenario blockers are removed to put the focus on exploration.
- The goal is to find the crests (7 by default), open Lake Shrine with them and beat Melzas.
- Arbitrary conditions from the original game stay when relevant (e.g. Secret Pass to open the Casino).
- Keys (including the Elevator Key) are not shuffled, to keep dungeon flow similar to the vanilla game.

## Requirements

- Java 17 or newer.
- Your own copy of Alundra (USA) **v1.1**, as a raw `.bin` image (single track, 600,359,760 bytes).

## Usage

Build the jar (or use a release package), then put your disc image next to it as `input.bin`:

```
java -jar alundra-randomizer.jar --preset=default
```

This writes `<hash sentence>.bin` / `.cue` (the randomized game) and `<hash sentence>.json` (the spoiler log) in the
current folder, and prints a **permalink**. Anyone can rebuild the exact same seed with:

```
java -jar alundra-randomizer.jar --permalink=<permalink>
```

The release scripts `gen_preset.bat` / `gen_preset.sh` and `gen_permalink.bat` / `gen_permalink.sh` do the same
interactively and put seeds in a `seeds/` folder.

| Option | Description |
|---|---|
| `--preset=<name>` | Preset file name inside `presets/` (or a path to a JSON file). Asked if omitted, `default` otherwise. |
| `--permalink[=<link>]` | Rebuild the seed described by a permalink (asked if no value given). |
| `--seed=<n>` | Fixed seed (0 to 4294967295) instead of a random one. |
| `--input=<path>` | Original disc image. Default `./input.bin`. |
| `--outputrom=<path>` | Output `.bin` path, or a folder. |
| `--outputlog=<path>` | Spoiler log `.json` path, or a folder. Default: next to the output image. |
| `--only-logic` | Only randomize and write the spoiler log (no disc image needed). |
| `--seedcount=<n>` | Generate several seeds in a row. |
| `--debuglog=<path>` | Write the shuffler's step-by-step log. |
| `--graph` | Write the logic graph as `logic.dot` (render with `neato -Tsvg logic.dot -o logic.svg`). |
| `--dumpmodel` | Dump the logic model, as altered by options, into `json_data/`. |
| `--noimagecheck` | Skip the input image size check. |
| `--pause` | Wait for Enter before exiting (used by the `.bat` scripts). |

## Presets

Presets are JSON files (comments allowed) with two sections. See [`presets/default.json`](presets/default.json) for
every setting with its documentation. Highlights:

- `gameSettings`: original japanese balance, megaliths active on start, skip last dungeon, split boots effects,
  progressive items, King Snow death count, casino win count, starting health / mana / gold.
- `randomizerSettings`: spoiler log allowed or not, starting inventory, crest count, fixed item sources, item sources
  that can't hold progression, and the item distribution (how many of each item are scattered in the world).

A spoiler log can also be used as a preset: its settings sections are read and the rest is ignored.

## How it works

1. **Model** (`model/`, data in `src/main/resources/data/`): the world is a graph of *nodes* linked by *paths*
   requiring items or other visited nodes. *Item sources* (chests, shops, rewards) live in nodes, *regions* group
   nodes, *hint sources* are characters giving hints.
2. **Shuffling** (`logic/WorldShuffler`): a solver explores the graph until it gets blocked, then a random blocked
   path is opened by placing the items it requires in already reachable sources (with weights limiting the
   first-sphere bias). This repeats until the end is reachable, then remaining items are placed randomly. The minimal
   set of required items is computed for the playthrough section of the spoiler log, and hints are generated with
   additional solving ("is this region needed?", "where is that item?").
3. **Patching** (`patches/`): 25 patches edit `DATAS.BIN` (maps, events, texts) and the executables: item source
   contents, new game state, cutscene removal, text fixes for shops and NPCs, progressive items (injected MIPS code
   generated by a small assembler in `tools/MipsCode`), etc.
4. **Disc image** (`iso/`): the image is read directly (ISO 9660 parser), patched files are written back in place
   and the following sectors are shifted when a file grows, exactly like a dump/rebuild with mkpsxiso would lay
   them out. Directory records, path tables and the volume descriptor are updated, and sector headers and EDC/ECC
   codes are regenerated. XA audio and video streams are copied untouched.

All randomness comes from a Mersenne Twister identical to C++'s `std::mt19937`, which is why seeds and permalinks
are compatible with the original randomizer.

## Differences with the C++ version

- **No external tools**: the original needed `dumpsxiso` / `mkpsxiso`; this version reads and writes the image
  itself.
- Video files are disabled by patching the executables (as in the original) but are left on the disc instead of
  being removed.
- The starting inventory is taken into account by the logic (the C++ solver discarded it, so a preset starting with
  e.g. a Bomb and no Bomb in the item pool could not be generated).
- `seed` is accepted inside a preset, `--seed` on the command line, and spoiler logs can be reused as presets (the
  settings key is now spelled `itemsDistribution`, the misspelled `itemsDistributions` is still accepted).
- A stray quote in the Coal Mine hint dialogue was removed.
- No runtime dependency (the JSON parser is built in).

## Verification

The port was checked against the original C++ build:

- **Logic**: 100 seeds over 4 presets (default, non-progressive with 3 crests, non-split boots with 0 crests and
  full Lake Shrine, no spoiler log) produce byte-identical spoiler logs and shuffler debug logs. Two of these
  reference logs are part of the unit tests (`ReferenceParityTest`).
- **Patches**: on synthetic game files (random bytes plus the structures patches read), every patched file
  (`DATAS.BIN`, `ALUN_CD.EXE`, `SLUS_005.53`, `END.EXE`, `CLOSING.EXE`, `ETC_USA.R`, `BALANCE.BIN`) is byte-identical
  to the C++ output for 16 seeds over 6 presets, including casino, King Snow, starting stats and balance settings.
- **Disc image**: a synthetic Mode 2 image rebuilt by the full command line pipeline was validated with an
  independent ECM encoder (every sector's EDC/ECC recognized) and an independent ISO 9660 reader (pycdlib), and the
  files read back from it are identical to the C++ patched files.

Not verified here: running a generated image on real hardware or an emulator, since that requires the copyrighted
game. Please report any issue.

## Project layout

```
src/main/java/com/alundra/randomizer/
  Main, Randomizer, RandomizerOptions     command line, high-level API, settings & permalinks
  game/      items, flags, map codes, room strings
  model/     world graph: nodes, paths, item sources, regions, hint sources
  logic/     WorldSolver (reachability) and WorldShuffler (item & hint placement)
  patches/   game patches
  iso/       raw CD sectors (EDC/ECC), ISO 9660 reader, image rebuilder
  io/        spoiler log, Graphviz and model writers
  tools/     byte arrays, MIPS assembler, Mersenne Twister, JSON, bitstreams, textbox formatter
src/main/resources/   logic data (JSON), default preset, japanese balance file
```

The item location maps and the seed tracker live in their own repository,
[alundra-item-tracker](https://github.com/gomezAlvaro/alundra-item-tracker). It keeps a copy of the logic data in
`src/main/resources/data`, so refresh it there (`scripts/sync_data.sh`) when that data changes.

## Archipelago mode

`--archipelago=<patch.json>` builds a game for an [Archipelago](https://archipelago.gg) multiworld instead of
randomizing: the patch file is written by the Alundra APWorld (see `scripts/ap/`), and lists the item of each
chest. Items of other worlds are shown as an "Archipelago item" that gives nothing. The patched game keeps a mailbox
in RAM that the Archipelago client uses to give items and show messages, and the client detects opened chests with
the story flag stored in each chest (`scripts/ap/extract_flags.js` extracts them from the disc data).

```
java -jar alundra-randomizer.jar --archipelago=<patch.json> --input=<disc.bin> --outputrom=<output.bin>
```
